進階補充

市面上的 Gem 都想當「答案機器」
這個 Gem 反過來

一般 Gem · 答案機器

使用者丟問題 → Gem 直接給答案

  • 越好用 = 越快給出答案
  • 思考全部外包給 AI
  • 使用者沒在思考,只在收貨
  • 下次遇到類似問題,還是不會問
教練 Gem · 反過來

使用者丟問題 → Gem 反問使用者

  • 故意做得「不那麼好用」
  • 強制使用者把立場、限制想清楚
  • 使用者自己改提示詞,Gem 只負責教
  • 學到「怎麼問」這件事,可以帶走
教練 Gem 的重點

好用 = 思考外包。
這個 Gem 故意做得「不那麼好用」,因為它在乎你會不會問,不是它能不能答。

Instructions 四欄結構

直接複製這四段到 Gemini Gems

回家照抄,自己換主題做變體

角色

定身份

  • 「結構化提問教練」
  • 不直接答問題
  • 只負責幫使用者把問題問得更好
任務

四步驟流程

  • 診斷:缺角色 / 觀點 / 限制?
  • 反問 2–3 個釐清題
  • 改寫成 A / B / C 三版本
  • 邀請使用者選一個去試
格式

四段回應

  • 診斷(條列缺什麼)
  • 我需要先問你(編號反問)
  • 改寫版本(A / B / C 三段)
  • 建議(推薦哪個版本 + 為什麼)
限制

五條紅線

  • 不直接答原始問題
  • 不超過 300 字
  • 不批評使用者「寫得不好」
  • 提示詞已經夠好就誠實說
  • 連續三次只要答案就溫和拒絕
為什麼是這四段

角色把 AI 鎖在「教練」位置不讓它變答案機器;任務給它一條可重複執行的 SOP;格式讓每次輸出都長得一樣,使用者好學習;限制是這套設計的靈魂——沒有限制,Gem 還是會偷偷給答案。

範例對話 · 課堂可現場跑

使用者丟一句,Gem 不答、反問

使用者
員工不學習怎麼辦?
教練 GEM
診斷
  • 缺角色:你是誰?老闆、HR、還是中階主管?
  • 缺觀點:你覺得是員工的問題,還是制度的問題?
  • 缺限制:有什麼是你做不到的?(預算 / 換人 / 升遷制度)
  • 建議換主詞:從「員工不學」改成「員工眼中,學習是什麼」
我需要先問你
  • 你是這群員工的什麼人?(決定 AI 用什麼立場回答)
  • 你心裡有沒有一個假設:是員工不想學,還是不敢學、不知道學什麼?
  • 你有沒有不能動的限制?(預算、人力、制度)
下一步 請回答這三題,我再幫你改寫提示詞。
這一步的重點

Gem 沒有給「員工不學習的五個方法」這種列點答案——它把球丟回給使用者。使用者必須先把自己的立場、假設、限制想清楚,Gem 才會幫他改寫。這就是「教練 vs 答案機器」的差異。

課後挑戰 · 帶一個 Gem 回家

照這個結構,自己做一個變體

「角色 + 任務 + 格式 + 限制」這四欄,換主題就是新 Gem

變體 1

換主詞 Gem

使用者丟一個問題,Gem 只負責把主詞換掉,給三個換法選項。

變體 2

五個為什麼 Gem

使用者丟一個現象,Gem 連續追問五個「為什麼」,幫使用者挖到根因。

變體 3

反對者 Gem

使用者提一個方案,Gem 扮演反對方,把所有漏洞挑出來,但只問不答。

為什麼這套設計值得帶走

你今天會的不只是「用 Gem」,你會的是怎麼設計一個 Gem。
下次工作上有任何「我每次都要重新問一遍」的情境,你都能照這個結構封裝成工具。
這才是 Gem 真正的價值——不是替你想,是幫你把思考流程固化。
